# 啄坊君への実装指示書 日足の非線形解析

更新日：2026年11月1日

## 目的と担当

あなたはClaude Codeとして、この解析ソフトの実装と保守を担当してください。学生が「今年の時系列を取得する → 数値と図を読める形で解析する → 投稿調査と対応づけて学会発表へまとめる」の3段階に到達できることが目的です。コードが動くことに加え、何を測った数値かを利用者が説明できる状態にしてください。

解析条件と結果の解釈は菊坊側でも検証します。未検証の手法を独断で増やさず、変更理由と数値への影響を残してください。

既存の授業用Webアプリとデータベースは今回の変更範囲に含めません。対象ブランチ上で変更を記録し、mainへの統合はPRでレビュー可能な状態にしてください。

## 最初に現状を再現する

1. 現在のコミットを記録し、既存コードを変更せずに以下を実行してください。

```bash
cd research/hurst_daily
python -m pip install -r requirements.txt
python run_student.py --demo
```

2. `results/`配下の`results.csv`、`scales.csv`、`audit.json`、出力図、`largest_moves_top5.csv`を確認してください。合成データへ入れた対数収益率0.13が変動上位1位かつ確認候補になることを確認してください。
3. H_RS、alpha_DFA1、点数、尺度範囲と実行環境を変更前の基準として保存してください。合成デモを実相場の解析結果とは扱わないでください。

## ステップ1 入力の来歴を明確にする

第一候補は2026年1月から取得時点の最新確定日までの日足です。ただし、日足を使う理由を研究の問いと投稿調査の時間尺度に結びつけて説明してください。現物指数・先物・CFDを同一視しないでください。

取得元、銘柄、足、対象期間、タイムゾーン、日時が表すもの、終値の定義、確定足かどうかを記録する入力メタデータを用意してください。先物では限月接続と価格調整も記録します。不明は「未確認」とし、CSVの時刻だけから意味を決めないでください。

入力時には、日付の昇順、重複、欠損、非正価格、短すぎる標本を点検し、修正方法が分かる日本語のメッセージを表示してください。休日や欠測を無断で補間せず、元データを保持してください。

取得に失敗した場合は、取得先、試した操作、具体的な障害を報告し、別の実行可能な取得方法を提示してください。取得待ちでも、合成デモによる実装確認と手順の整備は進めてください。現版は日足専用です。4時間足の対応は今回の必須作業にしません。

**到達条件：** 学生が入力期間・本数・来歴を確認でき、使えない入力では理由が分かること。

## ステップ2 数値と図を説明できるようにする

既存のR/SとDFA1を維持し、次をまとめた日本語の結果概要を出力してください。

- H_RSとalpha_DFA1、収益率点数、使用尺度の最小・最大、尺度ごとの窓数。
- 価格・対数収益率、スケーリング、変動上位5日、外れ値候補への参照。
- 入力データのハッシュ、実行条件、コードの版を追跡できる情報。

H_RSとalpha_DFA1を自動的に同一の指数とせず、0.5との大小だけで予測力や持続性を断定しないでください。直線への当てはまりと、統計的有意性を区別してください。約200点の日足は短標本であり、尺度範囲の制約を明記してください。

外れ値候補は削除対象ではありません。実際の大変動、限月接続、欠測、取得ミスなどを原資料で確認するための印です。平滑化や候補の自動除去は追加しないでください。尺度の自動選択、信頼区間、日々のHの推定は別途設計が必要です。

**到達条件：** 学生が「どの数値を報告するか」「どの図の何を見るか」「どの日を原資料で確認するか」を迷わず説明できること。

## ステップ3 投稿調査と学会発表へつなぐ

実データを含まない対応表のテンプレートを用意してください。列は、調査方式、媒体、対象日、個別根拠URL、公開日時とタイムゾーン、元スコア、確認状態、対応取引日、終値確定時刻、終値前後、収益率、観察メモとします。

検索型と固定発信者型を区別し、未調査・投稿未確認・中立を別に扱ってください。元スコアを書き換えず、時刻が不明な記録を自動結合しないでください。休日の投稿をどの取引日へ対応させるかは規則として残し、結果を見て都合よく変更しないでください。

変動上位5日前後の確認を入口とし、投稿調査との重複期間を必ず確認してください。重複しない場合は「対応する記録なし」と報告します。変動の大きい日を選んだ探索であることを明記し、一致しない例も残してください。全期間から一つ得たHと日別心理スコアの相関は作りません。

学会用の整理項目は「目的・データ・方法・確認済みの結果・限界」です。公式様式を取得してから配置し、未実行の結果欄を埋めないでください。まずは学生が各段階の成果を報告できる手順を完成させます。

**到達条件：** 対応表の記入方法と、学会発表に使える事実・保留する解釈の区別が明確であること。

## 公開と検証

このリポジトリは公開です。コード、手順、空のテンプレート、明示した合成サンプルを対象とし、個人の調査記録、連絡履歴、認証情報、再配布条件が確認できない相場データをコミットしないでください。実データのローカル出力が誤って含まれないようにしてください。

変更に応じて、合成デモの再実行、同一入力・同一条件での変更前後の数値比較、不正入力の拒否、結果概要と実際のCSVの整合を確認してください。実行していないOSを動作確認済みと書かないでください。数値が変わった場合は、丸め誤差か計算条件の変更かを説明してください。

## 納品物と完了報告

納品は、改訂コード、日本語手順、入力メタデータのひな型、日本語結果概要、投稿と価格の空の対応表、検証記録を一つのPRにまとめてください。依存ライブラリと起動方法を明記し、GitHubから取得した状態で合成デモを再実行できることを確認してください。

報告は次の5点で簡潔にまとめてください。

1. 何が使えるようになったか。
2. コミットとPRのリンク。
3. 実行した確認と、その結果。
4. 実データで未確認の点や障害。
5. 学生が次に行う一つの操作。

学生には、最初から完成した結果を求めず、取得したCSV、最初の図、困った画面を順に報告できると伝えてください。観測から何を言えるかを自分で確かめる楽しさを、具体的な到達点とともに示してください。
