# 啄坊君への指示書｜日足解析を学生が使える形にする

更新日：2026年11月1日

## まず、この場所で作業してください

| 項目 | 指定 |
|---|---|
| リポジトリ | `mune-king/AI-Decision-Lab` |
| 元にするブランチ | `research/hurst-daily-handoff` |
| 作業フォルダ | `research/hurst_daily/` |
| 起動するファイル | `run_student.py` |
| 計算するファイル | `analyze_daily.py` |

**今回の対象は、可児君の「市場価格の日足解析と投稿調査」です。**
蟻・歩行モデルのリポジトリとは別です。指定場所が開けなければ、見つからないパスとエラーをすぐ報告してください。別の研究へ置き換えないでください。

## 今回のゴール

学生が次の3つを自分でできるように、コードと日本語の手順を整えてください。

1. **2026年の日足を取得し、使えるデータか確認する。**
2. **解析を実行し、数値・図・変動の大きい日を説明する。**
3. **以前のX調査と対応を調べ、学会用紙にまとめる。**

あなたはソフトと手順を整えます。学生は自分のデータで実行・観察・報告します。菊坊側は解析条件と解釈を検証します。学生の未実行部分を「完了」と書かないでください。

**最初に、問いに合うデータかを確認します。** 入手しやすいだけで日足を正解にせず、「日単位の価格変動と投稿記録を調べる入口として使う」と説明してください。終値・日付・集計方法が分からないデータは、計算できても実証結果として確定しません。

## 着手時に一度だけ行うこと

現在のコミットを記録し、コードを変更する前に実行してください。

```bash
git clone --single-branch --branch research/hurst-daily-handoff https://github.com/mune-king/AI-Decision-Lab.git
cd AI-Decision-Lab/research/hurst_daily
python -m pip install -r requirements.txt
python run_student.py --demo
```

既に取得済みなら、現在の作業を保護したうえで指定ブランチを確認してください。Windowsでは必要に応じて `python` を `py` に置き換えます。

`results/実行時刻/` に数値と図が出ることを確認し、変更前の出力を比較用に保存します。合成デモでは、意図的に入れた対数収益率0.13が変動上位1位かつ確認候補になることを確認してください。**これは起動練習であり、市場の研究結果ではありません。**

## ステップ1｜今年の日足を用意する

### あなたが整えるもの

- 学生が日足CSVを保存して入力するまでの短い手順。
- 取得元・銘柄・期間・本数・足・タイムゾーン・終値の定義を記入するひな型。
- 入力に問題があるとき、原因と直し方を示す日本語メッセージ。

### 学生にしてもらうこと

1. 2026年1月から取得時点の最新確定日までの日足を取得する。
2. 元CSVを保存し、解析用のコピーを作る。
3. 現物指数・先物・CFDのどれかを記録する。先物なら限月のつなぎ方と価格調整も記録する。
4. 日付順、一日一行、重複・欠測・非正価格・未確定足を確認する。休日の行を追加したり、欠測を勝手に補間したりしない。

入力列は `datetime,close` または `time,close` です。`time` はUnix秒です。日時は提供元の意味とタイムゾーンを確認し、不明な時刻を作って埋めないでください。

まず日足で一巡させます。**現行コードは4時間足に対応していません。** 4時間足の追加は今回の必須作業にしません。

### 学生の報告例

> ステップ1：取得元URL＝○○、銘柄＝○○（現物／先物／CFD）、日足、期間＝○月○日～○月○日、価格○本です。終値と日付の定義は○○です。未確認は○○です。CSVを添付します。

取得できなければ、その時点で「試した取得先・操作・止まった画面またはエラー」を報告できるようにしてください。同じ失敗を繰り返させず、具体的な代案を返します。取得待ちの間も、あなたは合成デモで手順の整備を進めてください。

**完了の目印：入力期間・本数・出所・未確認点を説明できる。**

## ステップ2｜解析して、数値と図を読む

### あなたが整えるもの

既存のR/S・DFA1を使い、学生が読む数値と図をまとめた `RESULT_SUMMARY_JA.txt` を自動出力してください。新しい解析法を増やすより、現行出力を説明できることを優先します。

### 学生にしてもらうこと

ステップ1で点検したCSVを使います。

```bash
python run_student.py my_daily.csv
```

`my_daily.csv` は実際のファイル名に置き換えます。最終行が未確定と確認できた場合だけ `--drop-last` を付け、その判断を記録します。

| 開くファイル | 見る場所・報告すること |
|---|---|
| `results.csv` | R/S行の `exponent` が **H_RS**、DFA1行の `exponent` が **alpha_DFA1**。収益率の点数 `returns_used` と尺度範囲 `min_scale/max_scale` も報告する |
| `prices_returns.png` | 上段の価格、下段の対数収益率。大きな上下や不連続がどこにあるかを見る |
| `scaling.png` と `scales.csv` | 横軸は尺度。点が直線から曲がっていないか、各尺度で窓が何個あるかを見る |
| `return_diagnostics.png` と `largest_moves_top5.csv` | 変動の大きい上位5日を確認する。赤点は外れ値の「確認候補」 |
| `outlier_candidates.csv` | 候補の日付と値を原資料で照合する。実際の大変動、限月交代、欠測、取得ミスなどを調べる |
| `audit.json` | 入力期間・本数・データのハッシュ・実行条件を確認する |

結果概要には、上表の主要数値、尺度ごとの窓数、図の保存先、入力ハッシュ、コードの版、未確認点を載せてください。

### 解釈で守ること

- **外れ値候補は削除指示ではありません。** 現版の基準は中央値とMADによる `|modified_z| > 3.5` です。候補ゼロでも上位5日は確認します。MADが0ならスコアは算出できません。
- H_RSとalpha_DFA1は別々に報告します。0.5との大小や高い `loglog_R2` だけで、予測力・統計的有意性を主張しません。
- 約200点の日足では尺度範囲が限られます。長期記憶の証明や「毎日のHが分かった」とは書きません。
- 候補の自動削除、平滑化、都合のよい尺度選びは追加しません。
- 過去の報告値に合わせて条件を変えません。異なる値が出たら、その条件と値を残します。

### 学生の報告例

> ステップ2：H_RS＝○○、alpha_DFA1＝○○、収益率○点、尺度○～○点です。図を添付します。上位5日のうち○月○日は原資料で○○を確認し、○月○日は原因未確認です。スケーリング図では○○が見えます。

**完了の目印：数値の所在、図で見たこと、原資料で確認する日を説明できる。**

## ステップ3｜X調査とつなぎ、学会用紙にまとめる

### あなたが整えるもの

- `X_PRICE_TEMPLATE.csv`：投稿調査と価格を対応させる空の表。
- `STUDENT_3STEPS_JA.md`：学生向けに、操作と報告例だけを短くまとめた手順。
- 学会用紙に入れる項目の案内。実データの結果欄は学生の出力を確認してから記入する。

対応表の列は、調査方式、媒体、対象日、個別根拠URL、公開日時・タイムゾーン、元スコア、確認状態、対応取引日、終値確定時刻、終値前後、対数収益率、観察メモとします。

### 学生にしてもらうこと

1. **価格と投稿調査が重なる期間を確認する。** 検索型と固定発信者型、Xと他媒体を分ける。
2. 変動上位5日の前後1営業日を入口に、記録がある範囲で投稿内容・時刻・スコアを照合する。対応する記録がなければ「記録なし」とする。
3. 目的・データ・方法・確認できた結果・限界の順に、学会用紙へまとめる。

**未調査・投稿未確認・中立は別です。** 空欄を0にせず、元スコアを保持します。日別の集計点を複数投稿に複製して、独立した観測を増やさないでください。

投稿が終値より前か後かを確認します。終値後の投稿を同日の値動きの先行説明には使いません。休日の対応規則は比較前に決め、時刻不明の記録は保留します。

一致しない例も残してください。上位5日の確認は探索的な観察です。少数例の一致から予測成功や因果関係を主張しません。**全期間で一つ求めたHと、日別の心理スコアの相関は計算しません。**

### 学生の報告例

> ステップ3：重複期間は○月○日～○月○日です。確認できた対応は○件、時刻不明で保留は○件です。一致した例は○○、一致しない例は○○です。対応表と予稿の下書きを添付します。

学会の締切・公式様式を確認し、取得できた公式様式を使ってください。様式が取得できなければ、上の5項目で文章を準備し、障害を報告します。講演申込の最終送信はこの実装作業に含めません。

**完了の目印：確認済みの結果と保留する解釈を分けた、対応表と予稿下書きがある。**

## 啄坊君の納品と確認

指定ブランチを基点に作業用ブランチを作り、次を一つのPRにまとめてください。mainへの統合はレビュー後とします。

- 改訂コードと起動手順。
- 入力情報のひな型、日本語の結果概要、投稿と価格の空の対応表。
- 学生向け3ステップ手順。
- 検証記録：実行コマンド、環境、出力、未確認点。

確認するのは、①合成デモの再実行、②同一入力・同一条件での変更前後の数値比較、③不正入力の日本語案内、④結果概要とCSVの一致です。変更で数値が変わった場合は原因を書いてください。試していないOSを確認済みと書かないでください。

公開するのはコード、手順、空のひな型、合成サンプルです。個人の調査記録、連絡履歴、認証情報、再配布条件が不明な実相場データはコミットしません。

### 完了報告は、この形で

> 使えるようになったこと：○○  
> PR・コミット：URL  
> 実行した確認と結果：○○  
> 未確認・障害：○○  
> 学生が次にする一つの操作：○○

「作成した」「送った」「本人が実行できた」は区別して報告します。

学生には、最初から立派な結論を求めず、**CSVが取れた、図が出た、気になる日を一つ確かめた、という進歩を報告できる**と伝えてください。予想と違う結果も研究の成果です。観測したものから何が言えるかを自分で確かめる面白さを、一段ずつ経験できるように支えてください。
