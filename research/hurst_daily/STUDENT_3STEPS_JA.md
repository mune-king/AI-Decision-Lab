# 日足解析と投稿調査：学生用 3ステップ

立派な結論は最初から要りません。**「CSVが取れた」「図が出た」「気になる日を一つ確かめた」**も、それぞれ報告に値する進歩です。予想と違う結果も成果です。途中の図やエラーもそのままSlackに出してください。

## 0｜起動練習（5分）

Python 3.10以上が必要です（動作確認済みはLinuxのPython 3.11と3.13）。

**フォルダの用意**：先生から渡されたZIPを展開するか、次のコマンドで取得し、`research/hurst_daily` フォルダへ移動します。以下のコマンドはすべてこのフォルダで実行します（Windowsで `python` が見つからなければ `py` に置き換えます）。

```bash
git clone --branch research/hurst-daily-handoff https://github.com/mune-king/AI-Decision-Lab.git
```

```bash
cd AI-Decision-Lab/research/hurst_daily
```


```bash
python -m pip install -r requirements.txt
```

```bash
python run_student.py --demo
```

`results/実行時刻/RESULT_SUMMARY_JA.txt` が出れば成功です。合成デモでは、わざと入れた対数収益率0.13（単純騰落率では約13.9%）の日（2026-05-25）が変動1位・確認候補になります。**これは乱数による練習で、市場の結果ではありません。**図の上部にも `SYNTHETIC DEMO - NOT MARKET DATA` と表示されます。合成データの日付は11月以降まで続きますが、実在の相場ではありません。参考値は H_RS＝0.5756、alpha_DFA1＝0.6561、収益率219点、尺度16～54点です。

動作がおかしいと思ったら `python verify_package.py` を実行し、最後の行が `ALL CHECKS PASSED` か確認してください。`FAIL` があれば、その表示全文を報告してください。

インストールで止まったら、OS・実行したコマンド・画面のエラー全文を報告してください。

## ステップ1｜今年の日足を用意する

日足は「日単位の価格変動と投稿記録を調べる入口」として使います。日付や終値の意味が分からないデータは、計算できても実証結果になりません。

1. 2026年1月から、取得時点で**確定している最新日**までの日足をCSVで保存する。
2. 元CSVはそのまま保管し、解析用にコピーを作る。
3. 解析用コピー（例：`my_daily.csv`）を `research/hurst_daily` フォルダに置く。別の場所に置く場合は、実行時にファイルの場所も含めて指定する。
4. 解析用コピーの1行目を `datetime,close`（例：`2026-01-05T15:30:00+09:00`）または `time,close`（Unix秒）にする。
5. 確認する：日付が古い順か、1日1行か、重複・欠測・0以下の価格・未確定の最終行がないか。
   - 休日の行を足さない。欠測を補間しない。提供元にない時刻を作らない。
6. `INPUT_INFO_TEMPLATE.txt` をコピーして（例：`my_info.txt`）記入する。種別は現物指数・先物・CFDのどれかを書き、先物なら限月のつなぎ方と価格調整も書く。分からない項目は空欄にして「未確認点」に書く。

現版は**日足専用**です。4時間足を入れると、同じ日に複数の行があるため停止します。

> **報告例**　ステップ1：取得元URL＝○○、銘柄＝○○（現物／先物／CFD）、日足、期間＝○月○日～○月○日、価格○本です。終値と日付の定義は○○です。未確認は○○です。CSVを添付します。

取得できない場合は、**試した取得先・操作・止まった画面またはエラー**を報告してください。代わりの方法を一緒に考えます。

## ステップ2｜解析して、数値と図を読む

```bash
python run_student.py my_daily.csv --info my_info.txt
```

ファイル名は自分のものに置き換えます。「データが不足しているため解析できません」と出た場合は、**尺度の指定を変えずに**、取得期間・取得漏れ・欠測・入力形式を確認します。解消できなければ、表示された期間・本数とエラー全文を報告してください。最終行が未確定だと**確認できた場合だけ** `--drop-last` を付け、その理由を記録します。入力に問題があると、原因と直し方が日本語で表示されます（その場合、結果は保存されません）。

まず `RESULT_SUMMARY_JA.txt` を開き、次の元ファイルで数値を確かめます。

| ファイル | 見ること |
|---|---|
| `results.csv` | R/S行の `exponent` が **H_RS**、DFA1行の `exponent` が **alpha_DFA1**。`returns_used`（収益率の点数）、`min_scale`/`max_scale`（尺度範囲） |
| `prices_returns.png` | 上段：終値、下段：対数収益率。大きな上下や不連続の位置 |
| `scaling.png`・`scales.csv` | 点が直線から曲がっていないか。各尺度の窓の数 |
| `return_diagnostics.png`・`largest_moves_top5.csv` | 変動の大きい上位5日。赤点は外れ値の**確認候補**。`log_return` が対数収益率、`return_percent` はその100倍で、単純騰落率ではない |
| `outlier_candidates.csv` | 候補の日付と値を原資料で照合（実際の大変動・限月交代・欠測・取得ミス） |
| `audit.json` | 入力期間・本数・データのハッシュ・実行条件 |

**読み方の約束**

- 確認候補は削除指示ではありません。候補がゼロでも上位5日は確認します。
- H_RSとalpha_DFA1は別々に報告します。0.5より大きい・`loglog_R2`が高い、だけでは予測力や有意性は言えません。
- 約200点の日足では尺度の上限が約50点です。「長期記憶を証明した」「毎日のHが分かった」とは書きません。
- 見栄えのために行を削除したり、尺度を選び直したりしません。

> **報告例**　ステップ2：H_RS＝○○、alpha_DFA1＝○○、収益率○点、尺度○～○点です。図を添付します。上位5日のうち○月○日は原資料で○○を確認し、○月○日は原因未確認です。スケーリング図では○○が見えます。

## ステップ3｜X調査とつなぎ、学会用紙にまとめる

`X_PRICE_TEMPLATE.csv` をコピーして使います（Excelで開けます）。

1. 価格データと投稿調査が**重なる期間**を確認する。検索型（A）と固定発信者型（B）、Xと他媒体は別の行・別の集計にする。
2. 変動上位5日の**前後1営業日**から始め、記録がある範囲で投稿内容・公開日時・スコアを照合する。記録がなければ「記録なし」と書く。
3. 目的・データ・方法・確認できた結果・限界の順に、学会用紙へまとめる（`PAPER_ITEMS_JA.md` 参照）。

**表の書き方**

| 列 | 書き方 |
|---|---|
| 調査方式 | 検索型／固定発信者型 |
| 個別根拠URL | 1投稿1URL。日別の集計値を複数投稿に複製しない |
| 公開日時・タイムゾーン | 例：`2026-05-25T14:10+09:00`。不明なら「時刻不明」とし、対応づけは保留 |
| 元スコア | 調査時の値をそのまま。空欄を0にしない |
| 確認状態 | 確認済み／投稿未確認／未調査／記録なし（**中立**はスコアの値であって、未調査とは別） |
| 終値前後 | 終値前／終値後／時刻不明。終値後の投稿を同日の値動きの先行説明に使わない |
| 対応取引日 | 休日の投稿の扱い（例：翌営業日に対応）は**比較する前に**決めて記録する |

一致しない例も必ず残します。上位5日の照合は探索的な観察です。少数の一致から予測成功や因果関係は言えません。**全期間で一つのHと、日別の心理スコアとの相関は計算しません。**

> **報告例**　ステップ3：重複期間は○月○日～○月○日です。確認できた対応は○件、時刻不明で保留は○件です。一致した例は○○、一致しない例は○○です。対応表と予稿の下書きを添付します。
