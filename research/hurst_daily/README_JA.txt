今回の到達点：自分で今年の市場データを取得し、結果の数値と図を読み、X調査との対応を報告する。
この配布物には実相場データを含みません。--demoは合成データだけの起動練習です。
以前の独立作成コードを基に、入力銘柄を決めつける図題を修正し、変動の大きい日の確認用出力を追加しました。
Claude/GitHub側コードを検証・統合した版ではありません。
v0.4の追加：入力エラーの日本語案内（原因と直し方）、結果概要 RESULT_SUMMARY_JA.txt の自動出力、
入力情報ひな型 INPUT_INFO_TEMPLATE.txt と --info、投稿と価格の空の対応表 X_PRICE_TEMPLATE.csv、
学生用手順 STUDENT_3STEPS_JA.md、予稿の項目案内 PAPER_ITEMS_JA.md、自己点検 verify_package.py。
解析の計算はv0.3から変更していません（合成デモで全出力が一致することを確認済み）。
学生はまず STUDENT_3STEPS_JA.md を読んでください。

【まず動かす】
Python 3.10以上が必要です。ZIPを展開し、そのフォルダで実行します。
python -m pip install -r requirements.txt
python run_student.py --demo
Windowsでpythonが見つからなければ、pythonをpyに置き換えてください。
Pythonをまだ入れていない・インストールが失敗する場合は、その段階でOSと画面をSlackで報告してください。

【自分のデータを入れる】
2026年1月から取得できる最新の確定日までの日足をCSVにします。
日付と終値の列名は datetime,close としてください。
例：datetimeは2026-01-05T15:30:00+09:00のような形式。
提供元の実際の日時を保ち、例の時刻をコピーして実データの時刻を作らないでください。
time（Unix秒）,closeの形式も使用可能です。
python run_student.py my_daily.csv --info my_info.txt
（my_info.txt は INPUT_INFO_TEMPLATE.txt をコピーして記入したもの。--info は省略可）
最終行が未確定なら、確定行だけを取得するか --drop-last を明示して実行します。
休日の行を足したり、欠測を補間したりしないでください。
この版は日足専用で、4時間足を入力すると同じ日に複数行があるため停止します。
まず日足で完成させ、4時間足は観測区切りを確認してから別に扱います。

【結果の場所・報告する数値】
results/実行時刻/ に毎回別フォルダで保存します。
RESULT_SUMMARY_JA.txt：主要数値・尺度ごとの窓数・上位5日・図の保存先・入力ハッシュ・コードの版・未確認点の概要。
results.csv：method=R/SのexponentがH_RS、method=DFA1のexponentがalpha_DFA1。
returns_used＝収益率の点数、min_scale/max_scale＝傾きを測った観測点単位の尺度範囲。
loglog_R2＝直線への当てはまりで、有意性・予測の正しさを示す数値ではありません。
audit.json：入力期間、本数、データSHA256、実行条件を記録します。
prices_returns.png：終値と対数収益率。大きな上下や不連続を確認します。
scaling.png：横軸が尺度、縦軸が変動量。点の曲がりや直線からのずれも報告します。
scales.csv：尺度ごとの変動量と窓数。傾きの計算根拠です。
約200点の日足では尺度の上限は約50点です。長期記憶の証明や日々のH推定には使いません。
0.5は独立な有限分散の収益率を考える際の参照値です。H_RS>0.5だけで持続性や予測力を断定しません。
DFA1のalphaはHと自動的に同一視せず、R/Sとの差もそのまま報告します。
scale_sensitivity.csvは該当する比較尺度がある場合のみ行が出ます。短い入力で空なのは異常ではありません。

【外れ値候補の場所と読み方】
return_diagnostics.png：赤点が|modified z|>3.5の確認候補。絶対収益率の大きい上位5日には日付を表示。
largest_moves_top5.csv：その5日の日付、終値、対数収益率％。候補がゼロでもこの表を確認。
outlier_candidates.csv：中央値とMADを使う記述的基準を超えた日の一覧。
return_diagnostics.csv：全日の収益率、modified_z、順位、候補フラグ。
MAD=0ではスコアは算出せず、上位5日の確認だけを使います。
候補はデータ誤りとは限りません。大きな実変動・限月交代・欠測・取得ミスを元データで確認。
自動削除も平滑化も行っていません。「削除すると見栄えが良い」を理由に削除しないでください。

【X調査との接続】
これまでのA：検索ヒット型、B：固定発信者追跡型を別々に保ってください。
今年の価格データと調査が重なる期間を確認し、日付・スコア・実際の投稿URL・投稿時刻・取得時刻を整理。
no_relevant_postや欠測は実際に中立と評価した値と区別し、空欄を勝手に0にして平均しません。
まず変動上位5日の前後1営業日について、投稿内容とスコアを価格図に対応づけて報告します。
投稿が終値の前か後かを区別。翌営業日との比較をする場合は、結果を見て都合よくずらさず対応規則を記載。
休日の投稿は日付を保ち、休日に価格を補完しません。対応先が曖昧なら別欄で保留します。
少数例の一致を予測成功や因果関係とは書きません。対応しない例も残してください。
全期間で求めたHとalphaは一組の数値で、日別の心理スコアとの相関は計算できません。

【報告は3回に分けてよい】
1：取得元URL・銘柄（現物/先物/CFD）・期間・足・本数・CSV。取得できなければ試した方法と障害。
2：H_RS、alpha_DFA1、点数、尺度範囲、価格/収益率/スケーリングの図、変動上位5日と確認内容。
3：X調査の重複期間・価格との対応表・一致/不一致の観察、学会用紙の下書き。
分からないまま抱え込まず、途中の結果をそのままSlackに出してください。一緒に解決できます。
